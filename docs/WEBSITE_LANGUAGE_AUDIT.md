# 公式サイトの多言語対応調査

## 対象と判定

全国データのうち東京以外で公式サイトURLを持つ43,083施設を対象にします。
異なるURLは42,311種類です。同じURLを使う別施設も施設IDごとに残します。
東京の既存データや、URLのない31,572施設を削除・補完する処理はありません。

`scripts/website-audit/audit.py` は、トップページから同じホストの外国人患者案内、
通訳、国際医療、英語版、外来・予約案内を優先して最大6ページ、深さ2まで取得します。
この範囲はサイト全ページの精査を意味しません。robots.txtの制限を守り、
robotsが取得できない場合も本文取得を止めます。PDF・画像・JavaScriptによる表示は
必要に応じて別途確認する対象として記録します。

結果は、本文取得、言語情報の確認候補、取得不可、時間上限による未着手などを区別します。
記載が見つからないことや取得できないことを「多言語非対応」とは扱いません。
機械翻訳、問い合わせ窓口のみの英語、患者自身が手配する通訳、否定文も候補になり得ます。
同じ法人の複数施設が使うページは、各施設への適用範囲の確認が必要です。

候補からアプリへ自動登録はしません。施設ID・名称・住所・公式URLを照合し、
診療の対応言語、医師／スタッフ／通訳の別、予約・料金・利用条件を原文で確認して、
`data/clinic-language-reviews.json` に出典URL、確認日、引用、HTMLのSHA-256とともに登録します。
公式サイトによる確認は、電話確認や本日の受入確認とは区別します。

## 実行

Python標準ライブラリのみを使います。通常のアプリ起動・ビルド・検索では実行しません。

```sh
python3 -m unittest discover -s tests -p test_website_audit.py
python3 scripts/website-audit/audit.py --limit 12 --workers 4
python3 scripts/website-audit/audit.py --workers 8 --max-pages 6
```

途中結果は `audit-output/sites/` にURLのSHA-256をファイル名として保存します。
同じ出力ディレクトリで再実行すると完了分を再利用します。
取得失敗を再試行する場合は `--retry-unavailable` を指定します。
再試行で失敗しても、以前取得できたページの記録は保持します。
結果の確認日時と出典ページの取得日時を参照してください。

出力は次のとおりです。

- `facility-results.csv.gz`: 施設IDごとの全対象行、本文取得数、判定・取得状態、最初の候補のURL・短い引用、確認日時。
- `site-results.jsonl.gz`: 全取得ページのURL、日時、SHA-256、候補、失敗理由。時間上限で未着手のURLも残します。
- `summary.json`: URL件数、実際に取得を試みた件数、本文取得件数、施設別状態の集計。
- `audit-cache/`: 候補があるページの本文と原HTML。SHA-256をファイル名に使用。各実行区分で圧縮後25MiBに制限。

CSVはUTF-8 BOM付きで、表計算ソフトの数式として評価されるセルをエスケープします。
`no_statement_in_retrieved_pages` は「取得した選択ページで候補を検出していない」の意味で、
サイト全体に記載がないと断定するものではありません。
`needs_evidence_review` と `needs_facility_identity_review` は人による確認待ちです。
`complete` は指定したページ数・深さでの処理終了を表し、言語対応の確認完了ではありません。

## GitHub Actions

クラウド環境の接続経路で多くの上流503が発生するため、同じ公開サイト調査を
`.github/workflows/clinic-language-audit.yml` から別の通常の実行環境でも行えるようにしました。
施設サイトのアクセス制限を回避する処理はありません。

専用ブランチ `codex/clinic-language-audit-20261020` への調査コードのpushで開始します。
ホスト名のハッシュで8区分に分け、同じホストへのアクセスは同一区分で直列化します。
各区分16ワーカー、ホストごとの間隔は0.5秒以上、robotsの指定間隔を優先します。
70分で新しい取得を止め、未処理の理由を保存します。90分のジョブ上限を設定しています。
同じ専用ブランチで調査コードを修正した場合は、新しい実行が古い実行を置き換えます。

ワークフローの権限はリポジトリ読み取りのみです。公式ActionsをコミットSHAで固定し、
チェックアウト後の認証情報の保存を無効にしています。研究結果はリポジトリへ自動pushしません。
公開ページのみを取得し、ログイン、問い合わせフォームへの送信、患者情報の送信は行いません。
ソースURLはHTTP/HTTPSと公開IPに限定し、資格情報付きURL、内部IP、非標準ポートを拒否します。
HTTPSの転送先がHTTPになる場合も停止します。

各区分の結果は `clinic-language-audit-0` から `clinic-language-audit-7` の
Actionsアーティファクトとして3日間保存します。`checkpoints.tgz` は再開用のURL別記録です。
アーティファクトは実行結果の保存先であり、本番アプリが読み込むデータではありません。
レビューした根拠の登録やプレビュー反映は別途行います。
