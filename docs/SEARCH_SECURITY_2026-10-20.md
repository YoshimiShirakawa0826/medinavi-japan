# 検索環境とセキュリティ改善 — 2026-10-20

全国87,870施設を検索できる開発環境を用意しました。Next.js 16.4.2 / Node.js 24.xを使用します。
公開Vercelサイトへの反映は別途デプロイが必要です。

## 脆弱性と詳細API

- Next.jsとeslint-config-nextを16.4.2へ更新し、互換性を保てる間接依存も更新。
- `npm ci` で更新したロックファイルから再インストールできることを確認。
- `npm audit --omit=dev` はcritical/high/moderate/lowすべて0件。
- 全依存の監査には開発専用のhighが5パッケージ分残っています。
  根本原因は未修正の `braces <=3.0.3` で、eslint-config-next →
  @next/eslint-plugin-next → fast-glob → micromatch → braces の同じ依存経路です。
  https://github.com/advisories/GHSA-vfj7-8cjw-p6xm
- 確認時点のbraces公開最新版は3.0.3でした。監査が提案するeslint-config-next 14系への
  強制ダウングレードは行っていません。Lintはこの開発用依存を使用します。
  本番の検索/詳細APIのファイルトレースにこれらのLint用依存が入らないことを確認しました。
  開発・CIで悪意ある深いglobパターンを処理する危険は残るため、上流の修正公開後に追従してください。

詳細APIは都道府県全体のgzip展開を廃止し、施設IDの索引から1施設だけ読みます。
存在しないIDはデータ全件を展開せず404を返します。SQLは入力をパラメーターとして渡し、
ID・診療科・言語・地域・選択件数・検索文字数も検証します。

## 検索データを小分けに取得

`/api/clinics/search` は都道府県、施設名/住所、診療科、対応言語、受診条件で
絞り込み、20件ずつ返します。総件数やページ数も返すので、全国全件を閲覧できます。
以前の全件JSON約45.9MBをブラウザで解析する方式は使いません。

現在地検索は、公開されている施設の位置とレコード番号だけ取得し、端末内で
距離計算・半径絞り込み・並べ替えを行います。現在地の座標はAPIへ送りません。
表示対象の20件は公開レコード番号で取得します。大きな位置索引の応答だけgzipで圧縮し、
対応しないクライアントには通常のJSONで返します。端末内の位置索引キャッシュは最大2条件です。
データの版が変わった場合は索引を取り直し、番号のずれによる別施設の表示を防ぎます。

検索APIの応答はprivate/no-storeにしています。外部地図を開く場合の地点送信は従来どおりです。

## サーバーと再利用

施設データは `data/generated/clinics.sqlite` に格納します。検索用の軽い列と詳細を別テーブルにし、
詳細は1施設単位の圧縮データです。DBは読み取り専用で開き、ページキャッシュを4MiBに制限。
全件をJavaScriptのMapに展開して保持する処理はありません。

ビルド時のファイルトレースにDBを含めます。確認した検索/詳細APIのトレース対象サイズは
各約98.1MBです。これは実際のVercelデプロイ成功を保証するものではありません。
Node.js 24.xが必要なため、package.jsonのenginesでも指定しています。

`npm run prepare:data` は元アーカイブ、マニフェスト、変換処理、関連する判定処理、
ロックファイル、Node.jsバージョンのハッシュを確認します。生成したDBとcoverage.jsonの
ハッシュも一致すれば再生成しません。入力変更、生成物欠損・不一致の場合は検証済みの
アーカイブから再生成します。ハッシュはストリームで計算し、DB全体をメモリへ読みません。
データを変更して再生成した場合は、開発サーバーを再起動してください。

```bash
npm ci --cache /workspace/.npm-cache --no-audit --no-fund
npm run dev -- --hostname 0.0.0.0
```

初回のdev/build前にDBを自動生成します。通常起動では外部の医療サイトへの通信や
新しい認証情報は不要です。データ自体は2026-06-01時点の公的資料と、
既存の東京4,430施設の出典付き情報です。未確認の言語・電話・受診条件は推測していません。

## 検証結果

同一のローカル実行環境で本番モードを起動して測定しました。
本番回線・実端末・Vercelコールドスタートの性能保証ではありません。

| 確認内容 | 改善前 | 改善後 |
| --- | --- | --- |
| 全国検索の初期施設データ実転送 | gzip約5.51MB、全87,870件 | 約42.4KB、最初の20件 |
| 同じ検索の展開後データ | 約45.9MB | 約42.4KB |
| 不明な東京IDへの8件同時GETの完了 | 約2.36秒 | 約0.077秒 |
| 上記のサーバープロセス最大RSS | 約481MiB | 約112MiB |
| 東京/大阪の不明IDへ交互に8件GET | 約1.12秒 | 約0.026秒 |
| 現在地検索の全国施設位置索引 | 全施設レコードに含む | gzip約0.89MB、展開後約2.43MB |

- Lint成功、テスト39件成功、本番ビルド成功。
- スマートフォン幅で全国検索、北海道の検索/詳細/一覧復帰、沖縄への変更、大阪の症状検索を確認。
- 次の20件への移動、言語の未確認説明と条件解除、全国キーワード検索を確認。
- 現在地から3km以内の検索で1,383件を表示。APIリクエストにGPS座標がないことを確認。
- ブラウザが旧 `clinics.json` や都道府県別の全件JSONを取得しないことを確認。
- SQL文字列の混入、不正な地域/言語/診療科、20件を超すカード取得、データ版の不一致をテスト。
- 検索結果の詳細出典、元の東京施設と電話番号の保持方針は継続しています。

利用規約・プライバシーポリシーの運営情報整備と本番Vercelの権限設定は、この変更では
完了を確認していません。クラウド環境の設定保存・公開と、アプリの本番デプロイは別の操作です。
