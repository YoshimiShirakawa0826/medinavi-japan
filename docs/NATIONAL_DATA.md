# 全国データと検索（2026-10-20）

全国47都道府県、病院7,715件・診療所80,155件、合計87,870施設を収録。
歯科診療所票、助産所票、薬局票は今回の取り込み対象外です。
既存の東京4,430施設は全件同一IDが全国データに存在し、従来の電話・受診条件・
営業時間と出典をそのまま優先しています。合計は重複のない87,870件です。

## 情報の扱い

- 施設票のIDは都道府県2文字・機関区分1文字・施設コードです。施設コードは
  可変長で英数字を含みます。桁を補完せず、そのままナビイ詳細URLへ渡します。
- 施設名（日本語・公開されている英語表記）、住所、座標、公式サイト、診療科を取り込みます。
- 座標欠損・日本の範囲外は0/0として距離を非表示にします。
- 英語名やローマ字表記を、外国語診療・スタッフの語学力の根拠にしません。
  配布元に言語情報がない施設は未確認から開始し、公式サイトの記載を確認した施設だけ
  `data/clinic-language-reviews.json` の根拠に基づいて補足します。
  言語・医師/スタッフ/通訳の別・予約条件・原文引用・出典URL・確認日を施設詳細に表示します。
  機械翻訳だけのページ、問い合わせ窓口の対応、患者自身が手配する通訳は、
  診療言語の検索対象を増やす根拠にはしません。
- 電話・カード・保険・予約・救急対応を推測しません。電話未収録の場合は、
  対象施設のナビイ詳細ページから連絡先を確認できます。
- 診療科ごとの時間、受付締切、週ごとの休診があるため、新規施設の
  営業時間は未確認のままです。一般的な営業時間で受入可否を断定しません。
- 元の東京情報は新しい配布日で上書きしていません。診療時間・言語・
  アクセス条件のフィルタは、それぞれ根拠のある情報だけが対象です。
  「本日の英語対応」は日本時間の同日に電話・訪問で直接確認した情報だけを対象とし、
  公式サイトで一般的な英語対応が確認できても、本日の対応可否には使用しません。
- 収録数は配布された病院・診療所票の施設数です。全国すべての施設や、
  外国語で受診できる施設数を保証するものではありません。

## 配信と画面

`npm run prepare:data` が以下を作成します。生成物はGit管理外です。

- `public/data/coverage.json`: 47都道府県の件数と基準日。
- `data/generated/clinics.sqlite`: 検索用の索引と、施設単位で圧縮した完全な詳細レコード。
- `data/generated/setup-cache.json`: 入力と生成物のハッシュ。一致時は再生成を省略します。

`/api/clinics/search` はキーワード・都道府県・診療科・言語・受診条件で検索し、20件だけ返します。
詳細は `/api/clinics/[id]` が索引から1施設を取得します。不明なIDに対して全件を展開しません。
SQLiteは読み取り専用、ページキャッシュ上限は4MiBです。データベースは
`next.config.ts` の `outputFileTracingIncludes` で両APIのデプロイに含めています。
以前の全件JSON・都道府県別JSON・都道府県別gzipは生成しません。

現在地・駅からの距離検索では、条件に合う施設の公開座標とレコード番号だけ取得し、
現在地の座標を送らず端末内で距離計算・並べ替えを行います。大きな位置索引の応答は
対応ブラウザへgzip圧縮して返し、最大2条件分を端末のメモリに保持します。
選択された20件分の公開レコード番号でカードを取得します。データの版を照合し、
更新をまたいだ場合は位置索引を取得し直して別施設の誤表示を防ぎます。
検索APIの応答はprivate/no-storeです。自由入力や現在地を共有キャッシュに保存しません。

## 再生成と更新

Node.js 24で `npm ci` 後、次を実行します。

```bash
npm run prepare:data
npm run lint
npm test
npm run build
```

元ZIPからの再取り込みはPython標準ライブラリだけで実行できます。

```bash
python3 scripts/import-national-data.py --source-dir /workspace/medinavi-source --download
npm run prepare:data
```

既存のZIPは保存済みのSHA-256と照合します。同じ配布URLの内容が変わったときは
処理を止めます。新しい版を取り込む場合は、配布元のスキーマ・基準日・件数と
差分を確認するコード変更として行ってください。チェックサムを無効化したり、
既存の出典付き情報を別のIDへ移植しないでください。
