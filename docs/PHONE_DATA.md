# 電話番号の取得元と照合

## 元のナビイCSV

厚生労働省「医療情報ネットのオープンデータ」の診療所施設票を確認した。

https://www.mhlw.go.jp/stf/seisakunitsuite/bunya/kenkou_iryou/iryou/newpage_43373.html

- 2025-12-01版: `02-1_clinic_facility_info_20251201.csv`、62列、76,988施設。
- 2026-06-01版: `02-1_clinic_facility_info_20260601.csv`、62列、80,155施設。
- いずれにも電話番号列はない。ナビイのWeb画面に掲載される全項目がCSVに含まれるわけではない。
- アプリの4,430施設は、2025-12-01版と施設ID・正式名称・所在地が全件一致した。
- 2026-06-01版でも施設IDは全件存在し、名称・住所も同じものは4,327件だった。

   https://kouseikyoku.mhlw.go.jp/kantoshinetsu/chousa/shitei.html
   ZIP: https://kouseikyoku.mhlw.go.jp/kantoshinetsu/shitei_ika_r0809.zip
2. 医療情報ネット（ナビイ）の施設詳細画面の「案内用電話番号」。
   施設IDから作った詳細URLと、各施設の名称・住所を照合する。

厚生労働省の公表情報をMediNavi JAPANが抽出・整形したものであり、厚生労働省が本サービスの内容を確認・承認したことを意味しない。

## 誤照合を防ぐ条件

- 厚生局一覧の「現存」かつ「診療所」を対象とする。
- 全角・半角と空白、丁目・番地の表記を正規化し、施設名と街区までの住所を照合する。
- 法人名の有無だけが異なる名称は許容する。同じ街区に候補が複数ある場合は自動採用しない。
- ナビイIDの末尾が保険医療機関コードと同じとは限らないため、末尾コードだけで照合しない。
- ナビイ詳細画面では、同じ施設IDでも名称や所在地が変わっている場合は保留する。
- 同じ番号が別施設に割り当てられている場合はナビイで再照合する。個別に取得したナビイの案内番号を優先し、資料間の相違は報告書に残す。
- 「案内用電話番号」の欄だけを使い、FAX・予約専用・部署の電話番号は代用しない。
- 電話番号が不明、複数番号で曖昧、形式不正の場合は空欄のままとし、ナビイへの確認リンクを表示する。
- 電話番号と`phoneSource`以外の既存項目、施設ID、順番を維持する。

これは公開資料との照合であり、施設へ電話して通話・受診可否・対応言語を確認したものではない。
既存の`verification.status`を「確認済み」には変更しない。

## 更新用スクリプト

`scripts/enrich_phones.py`はPython 3標準ライブラリだけで実行できる。
元資料は`public/`の外に保存し、入力データに直接書き込まず、出力を確認してから反映する。

```bash
python3 scripts/enrich_phones.py \
  --clinics public/data/clinics.json \
  --source-dir /path/to/nabii-source \
  --output /path/to/clinics-enriched.json \
  --fetch-details --workers 4
```

元資料フォルダには`shitei_ika_r0809.zip`を置く。2026年9月の資料のハッシュをスクリプト内で固定しているため、
次の資料へ更新する際には列構成・対象日・ファイルを再確認してから更新する。
個別ページは取得済みファイルを再利用する。再取得したい場合は、該当キャッシュを別の場所に保管してから実行する。
詳細ページの取得は基本情報部分のみで終了するため、キャッシュが完全なHTMLページとは限らない。
401・403・429では新しい取得を停止する。既存電話番号と異なる候補は自動上書きしない。

`phone-reconciliation.json`に各番号の元表記、元施設名・住所、出典URL、照合方法、保留理由を出力する。
公開JSONの`phoneSource`には資料の基準日（該当時）と取得日を保持し、画面にも表示する。
`updatedAt`は他の施設情報の時点なので、電話番号の取得日で一括更新しない。
